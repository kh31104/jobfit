# Jobfit 개발 규칙

## 목적
Jobfit은 STEP 0부터 STEP 13까지 계속 수정·확장되는 수업용 커리어 프로그램이다. 한 STEP을 수정할 때 다른 STEP의 화면, 저장 데이터, 이동, 백업·복구, 수업 주소에 예기치 않은 변화가 생기지 않도록 아래 규칙을 기본 개발 원칙으로 적용한다.

## 1. 주차·STEP별 수정 범위 분리
- 각 STEP의 기능 수정은 해당 `v2/steps/stepN.js` 파일을 우선 수정한다.
- 다른 STEP 파일은 해당 STEP의 명시적 요구가 없는 한 수정하지 않는다.
- 한 STEP의 UI·프롬프트·내부 계산을 변경하기 위해 다른 STEP의 로직을 함께 재설계하지 않는다.

## 2. 공통 파일 변경 최소화
다음 파일과 기능은 여러 STEP이 공유하므로 보호 영역으로 취급한다.
- `v2/app.js`
- `v2/index.html`
- 공통 CSS
- 라우팅 및 STEP 이동
- 익명코드 생성·복구
- course 파라미터
- 저장·백업·복구 로직

공통 파일 변경이 불가피한 경우에는 변경 이유와 영향 STEP을 먼저 확인하고 전체 회귀 테스트를 수행한다.

## 3. 주소 안정성
기존 수업 주소와 쿼리 파라미터를 유지한다.
- 기본 수업 주소: `https://kh31104.github.io/jobfit/?course=INJE2026`
- 개별 STEP을 수정하기 위해 새로운 수업 주소를 만들지 않는다.
- 기존 `course`, `interest` 등 운영 파라미터의 의미를 임의로 변경하지 않는다.

## 4. 데이터 스키마 하위 호환성
- 이미 저장 중인 데이터 키를 삭제하거나 이름을 바꾸지 않는다.
- 새 기능은 가능한 한 optional 필드를 추가하는 방식으로 구현한다.
- 기존 downstream STEP이 참조하는 artifact 구조를 유지한다.
- 구조 변경이 꼭 필요하면 기존 필드를 유지한 채 새 버전을 병행하거나 migration 경로를 만든다.

예: STEP 1
- `assessments.careerDNA` 유지
- `artifacts.careerDNAProfile` 유지
- 새 기능은 기존 객체 안에 optional 필드로 추가 가능

## 5. STEP 간 데이터 계약
- 각 STEP은 다른 STEP의 내부 UI 상태나 세부 구현에 직접 의존하지 않는다.
- 다른 STEP에서 사용할 정보는 정해진 `assessment` 또는 `artifact` 출력만 사용한다.
- 내부 프롬프트·화면 구성은 바뀌어도 외부로 전달되는 핵심 데이터 계약은 유지한다.

## 6. 추가형 수정 원칙
기존 기능을 교체하기보다 다음 순서를 우선한다.
1. 기존 필드와 동작 유지
2. 새 기능 추가
3. 새 필드는 optional 처리
4. 기존 데이터가 없어도 렌더링 가능하도록 방어 코드 적용

## 7. 미실시·부분입력 허용
Jobfit의 검사·활동은 수업시간과 운영상황에 따라 일부만 실시될 수 있다.
- 모든 검사가 완료되어야 다음 기능이 작동하는 구조를 기본값으로 두지 않는다.
- 입력된 자료만 사용한다.
- 미입력 정보는 추정하지 않는다.
- 부분입력 자료는 상태를 표시하고 과도하게 해석하지 않는다.

## 8. 프롬프트 모듈화
AI 프롬프트는 가능한 한 `공통 Core + 현재 확보된 데이터 모듈 + 인터뷰 규칙 + 출력 규칙` 구조로 만든다.
- 학생별 검사 조합에 따라 필요한 모듈만 동적으로 포함한다.
- 존재하지 않는 검사결과를 프롬프트에 임의로 채우지 않는다.
- 새 검사나 활동이 추가되어도 기존 모듈을 깨뜨리지 않고 확장할 수 있어야 한다.

## 9. 저장 안전성
- STEP 이동 전에 현재 입력값을 기존 방식대로 저장한다.
- 새로고침 후 기존 데이터가 복원되어야 한다.
- 기존 JSON 백업·복구가 새 optional 필드 때문에 실패하지 않아야 한다.

## 10. 회귀 테스트
한 STEP을 수정한 뒤 최소 다음 항목을 확인한다.
1. 기존 수업 주소 접속
2. STEP 0 정상 진입
3. 수정 STEP 정상 렌더링
4. 기존 저장 데이터 로드
5. 수정 STEP 저장
6. 이전 STEP 데이터 유지
7. 다음 STEP 이동
8. 새로고침 후 데이터 유지
9. 백업·복구 호환성
10. 다른 STEP 렌더링 오류 없음

## 11. 변경 금지 기본 원칙
사용자의 명시적 요청이 없다면 아래 항목을 한 STEP 수정 과정에서 변경하지 않는다.
- 다른 STEP의 수업 내용
- 전체 STEP 순서
- 기본 수업 주소
- 익명코드 정책
- 연구제출 활성화 여부
- 중앙 저장 정책
- course 코드 의미

## 12. 변경 기록
기능 변경 시 커밋 메시지는 수정 STEP과 목적이 드러나도록 작성한다.
예:
- `STEP 1: add dynamic Career DNA prompt builder`
- `STEP 4: refine evidence interview without changing downstream schema`

## 최우선 원칙
> 각 STEP은 계속 개선할 수 있지만, 다른 STEP이 의존하는 주소·라우팅·저장 구조·출력 데이터 계약은 임의로 바꾸지 않는다.
